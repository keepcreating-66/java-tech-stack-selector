description: 导出当前已确认的 Java 技术选型配置或提示词
---

先在当前对话中查找**用户已经确认**的完整配置。若缺少架构、项目名、模块或关键组件，调用 `/start` 的文字选型流程补齐；不要根据旧预设静默推断。

`$ARGUMENTS` 支持 `json`、`md`、`xml`、`all`。未指定时给出编号并等待回复：`1 JSON 配置`、`2 Markdown 提示词`、`3 Maven XML 依赖片段`、`4 全部`。

- JSON 应包含当前架构、业务场景、模块/服务和选中的组件，只能使用已支持的选项。
- Markdown 提示词应按所选架构描述工程结构。微服务不得写成模块化单体；选 JPA 时不得要求 MyBatis-Plus Mapper。
- XML 依赖片段是**对话式候选输出**；应按所选组件纳入正确数据库驱动、ORM、缓存和安全依赖，并说明未经过构建验证。可运行工程以 VSIX 生成器及实际构建结果为准。

在聊天中给出内容即可。用户要求写入工作区文件时，先选目标路径、检查是否存在并避免覆盖；只有文件真正写出后才称“已导出”。不要默认保存到当前目录，也不要假定其他聊天轮次中有仍有效的配置状态。

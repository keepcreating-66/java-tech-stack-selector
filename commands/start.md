---
description: 按架构、业务场景和受支持技术栈引导 Java 后端项目选型
---

使用 `tech-stack-selector` Skill 完成选型。`$ARGUMENTS` 可以作为项目名候选，但仍需在最终总览中确认。

1. 先问架构：`1 单体`、`2 模块化单体`、`3 微服务`。逐项说明服务和部署边界，并等待用户回复编号或名称。单体/微服务可切换尚未开放。
2. 再问业务场景：`1 企业管理`、`2 电商`、`3 AI 应用`、`4 自定义`。预设只填写默认值，不能覆盖已选架构或直接生成。
3. 收集项目名与业务模块/服务名；默认可展示 `user`、`order` 并允许修改。随后询问当前首批支持的数据库、ORM、缓存、安全和 API 文档选项。微服务可继续询问是否生成网关；注册中心/RPC/熔断/分布式事务暂不作为可生成选项。
4. 询问输出：配置 JSON、提示词 Markdown、Maven 工程。对话命令提供配置/提示词内容；确定性工程由 VSIX 的 `Java Tech Stack: 开始技术选型` 生成。
5. 显示完整配置，包括架构、业务预设、模块/服务、Java 17、Spring Boot 3、Maven、各组件和输出方式。提供 `确认`、`修改某项`、`返回`、`取消`，等待明确选择。用户修改后重新显示总览；确认后选择目标目录再写文件，取消不写文件。若用户明确要求 Agent 在工作区创建工程，应按选项实际写文件、检查目录与依赖并报告构建状态。

对话选项使用文字和编号。不要把 `#单选:*` Markdown 锚点描述为可点击按钮，也不要假设点击链接会回传值。当前可生成范围和配置约束见 Skill 正文。

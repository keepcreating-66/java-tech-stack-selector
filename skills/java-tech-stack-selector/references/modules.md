# 架构与模块边界

选型先确定架构，再确定业务场景和模块名。默认的 `user`、`order` 只用于示例，允许用户修改；模块名应唯一并满足 Java 包名约束。

| 架构 | 工程边界 | 最小验收 |
| --- | --- | --- |
| 单体 | 一个 Maven 应用，各业务域作为代码包 | 一个启动类；示例端点与所选 ORM 一致 |
| 模块化单体 | Maven 父工程、`common`、至少两个业务模块、`bootstrap` | 业务模块经 Maven 依赖进入同一个启动应用 |
| 微服务 | Maven 父工程、至少两个独立服务及可选网关 | 各服务独立启动；网关启用时能路由到业务服务 |

微服务首批使用静态服务地址。注册/配置中心、服务间 RPC、熔断和分布式事务没有生成模板与验收，不作为当前可选组件。单体/微服务可切换架构尚未实现。

架构标签不能代替实际目录、构建模块和启动入口。导出提示词时也必须按选定架构描述结构，不能将微服务写成模块化单体。
